# 전체 로컬 단보루 자료의 VRS 관계 기억

`vrs_full.py`는 원본 `danbooru_unified/manifest.jsonl` 전체를 대상으로 하는 별도의
GPU 구축·조회 도구입니다. 작은 실험의 16,384개 관측·3,072개 태그 상한을 적용하지
않습니다. 이미지·태그 관측을 저장하고 공출현 횟수를 CUDA에서 계산한 뒤 기존 VRS
`association_scalar.hpp` 판정을 호출합니다. 새로운 신경망 학습, 전체 VRS 상주
런타임 통합, ComfyUI Writer 연결은 이 도구의 범위가 아닙니다.

**2026-10-11 이미지 입력 검사:** 기존 이미지 특징 캐시에서 픽셀을 정수로 변환한
문제를 재현했습니다. 태그 관측·관계 저장과 별개로, 기존 `vectors.npy`를 정상적인
이미지 태깅 품질의 근거로 사용하면 안 됩니다. 새 이미지 128장 검사와 수정 비교는
[이미지 입력 평가](IMAGE_RETRIEVAL.md)를 참고하세요. 원본 스냅샷은 보존했습니다.

## 보존과 제외 기준

- 작가·캐릭터·작품 태그는 핵심 정보입니다. 빈도 1도 보존하며 어휘 개수 상한이 없습니다.
- 원본의 `tags_artist`, `tags_character`, `tags_copyright`를 분류 근거로 사용합니다.
  분류가 없는 이름을 형태만 보고 추측하지 않습니다. 다른 원본 기록에 명시된 동일
  태그의 분류는 조회용 사전에 연결하되 각 원본의 실제 필드는 별도로 보존합니다.
- 파일·수집 메타 정보, 품질·해상도, 워터마크·서명 등을 `tag_policy.py`의 명시적
  목록과 제한된 패턴으로 제외합니다. 보수적인 목록이므로 알려지지 않은 메타 태그가
  남을 수 있습니다. 모든 meta 분류를 삭제하지는 않습니다. 예를 들어 `official_art`,
  `traditional_media`는 유지합니다. 핵심 이름 분류가 제외 규칙보다 우선합니다.
- 종전 caption 가공의 drop 목록을 쓰지 않습니다. 작품명까지 빠진 과거 가공을
  그대로 계승하지 않고 원본에서 태그를 다시 읽습니다. 종전 분할만 재사용합니다.
- 제외한 태그도 원본 레코드와 제외 사유를 SQLite에 남깁니다. 원본 데이터는 수정하지
  않습니다. 노출 등급 `g/s/q/e` 전체를 구축하고, CLI 예시 조회는 기본 `g,s`로 제한합니다.
- 이미지 SHA-256이 같으면 한 번만 셉니다. 같은 이미지에 붙은 여러 원본 기록의 태그는
  합집합으로 보존하고 모든 원본 ID를 연결합니다. 등급은 가장 엄격한 것을 사용합니다.
  train → val → test 순으로 대표를 선택해 동일 바이트 이미지의 분할 누출을 막습니다.
  다른 인코딩·크롭·유사 그림의 중복은 아직 검사하지 않습니다.

`A`는 **한 이미지의 기록에 해당 태그들이 함께 존재한다**는 범위입니다. 시각적 진실,
사용자 의도, 새 태그 추가 허용을 판정하지 않습니다. 태그 부재를 반박 증거로
간주하지 않으므로 관측되지 않은 관계는 암묵적 `U`입니다. 반박·충돌 경로는 합성
입력으로 기존 C++ 판정과 비교합니다.

## 실행과 자원 제한

CUDA PyTorch, NumPy, SciPy, NVRTC, C++17 컴파일러와 외부 VRS 헤더가 필요합니다.
CUDA 불가 시 CPU로 재시도하지 않습니다. 아래 명령은 4070 Ti SUPER의 UUID를
지정하며 CPU affinity·연산 스레드는 2개, 디스크 읽기는 2개 작업자로 제한합니다.
`nice`와 `ionice`로 기존 데스크톱·디스크 작업을 우선합니다. 실제 시스템의 경로와
GPU UUID에 맞춰 실행하세요. 이미 있는 출력 디렉터리는 덮어쓰지 않습니다.

```bash
nice -n 15 ionice -c 3 taskset -c 0,1 env \
  OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  CUDA_VISIBLE_DEVICES=GPU-c8460706-b04f-d00d-2a88-b036f96fc417 \
  /home/raspie/AI/ComfyUI/.venv/bin/python -m experiments.vrs_full build \
  --dataset /mnt/storage/Projects/danbooru_unified \
  --vrs-core /var/home/raspie/vrs9/core \
  --output /mnt/storage/Projects/rs_seasonal_vrs_full_next
```

공출현은 태그 128개씩 희소 GPU 행렬곱으로 계산합니다. 이미지 토큰 특징도 64건씩
읽고 GPU에서 평균·정규화한 768차원 FP16 벡터로 저장합니다. 기존 특징이 없는
이미지도 태그 관측으로 남깁니다. 특징 추출 모델의 원래 provenance는 미검증이며,
이 벡터는 텍스트와 정렬된 임베딩으로 취급하지 않습니다.

PyTorch 할당 한도는 GPU VRAM의 20%입니다. 이 한도는 CUDA 드라이버와 다른
라이브러리까지 포함한 절대 상한이 아닙니다. 0.5초 간격으로 프로세스 VRAM 표본을
수집하고, 프로세스 종료 시 GPU 문맥까지 해제합니다. 별도 Writer LLM이나 이미지
생성 모델은 이 측정에 포함하지 않습니다.

```bash
nice -n 15 ionice -c 3 taskset -c 0,1 env \
  OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  CUDA_VISIBLE_DEVICES=GPU-c8460706-b04f-d00d-2a88-b036f96fc417 \
  /home/raspie/AI/ComfyUI/.venv/bin/python -m experiments.vrs_full query \
  --memory /mnt/storage/Projects/rs_seasonal_vrs_full_20261011_v1 \
  --tags 'hatsune miku' --exclude 'twintails' --ratings g,s
```

쉼표로 여러 태그를 주면 모두 만족하는 관측만 사용합니다. 알 수 없는 필수 조건은
무시하지 않고 `U`로 반환합니다. 후보당 최소 근거 수는 기본 2건이며,
`--min-support 1`로 단일 관측의 관계도 볼 수 있습니다. **기본 조회에서 근거 2건을
요구하는 것과 저장에서 희귀 이름을 버리는 것은 다릅니다.** 제외 태그는 기록에
명시된 경우에만 제거되므로 실제 이미지에 없음을 보장하지 않습니다.

## 산출물과 검증 범위

| 파일 | 내용 |
| --- | --- |
| `receipt.json` | 완료 상태, 코드·원본·산출물 해시, VRS 헤더·PTX 해시, 검증·자원 결과 |
| `observations.sqlite3` | 전체 원본, 이미지 해시, 대표 ID, 유지·제외 태그와 이유 |

| `vocabulary.json`, `tag_categories.json` | 전체 보존 어휘와 원본 필드 기반 분류 |
| `pairs/*.npz`, `pairs.json` | 관측된 방향별 태그 관계 횟수, VRS 상태와 사유 |
| `vectors.npy`, `vector_mask.npy`, `features.jsonl` | 검색용으로 요약한 기존 특징, 존재 마스크, 원본 캐시 해시 |
| `ingest.json` | 처리 수, 제외 태그별 횟수, 분할·등급별 수 |
| `evaluation.json` | train만으로 계산한 test 태그 복원 검사와 개별 결과 |
| `queries.json`, `gpu_samples.json` | 조회 예시와 GPU 메모리 표본 |

완료 전 스냅샷은 일반 조회에서 거부합니다. 일반 조회 시 저장된 산출물 해시를
검증합니다. 평가용 관계는 train 관측만으로 다시 계산하며 전체 그래프를 사용하지
않습니다. test 이미지의 태그 3개에서 나머지 태그를 복원하고, 태그 전체 빈도·입력별
공출현·모든 입력의 동시 관측 방식의 P@10, R@10과 응답률을 비교합니다. 어휘 밖
태그 비율도 보고합니다. 이는 한국어 이해·인물별 의상 배정·프롬프트 자연스러움·생성
이미지 품질 평가가 아닙니다. 이전 작은 실험과 자료·어휘·제외 규칙이 달라 그 숫자를
직접 성능 향상률로 비교하면 안 됩니다.

신규 다운로드와 정기 실행, 수정 태그의 판본 갱신 정책은 아직 연결하지 않았습니다.
새 데이터의 현재 경로·판본을 확인한 뒤 새 출력 디렉터리에 재구축할 수 있습니다.
