May 18th, 2026  (v2.3.0)
1. Download progress on the node
The default-model download now shows a progress bar on the Gemma TIPO
node (ComfyUI ProgressBar) plus a console percentage, so a first-run
download no longer looks frozen. The file is streamed straight into
ComfyUI/models/gguf with the standard library; huggingface_hub is no
longer a dependency.

May 18th, 2026  (v2.2.0)
1. Model selection is now a dropdown
The Gemma TIPO node's free-text path input is replaced by a dropdown of
the *.gguf files found in ComfyUI/models/gguf, plus an
"(auto: download default)" entry that fetches the default model there on
first use.

2. Fix: enforce a gemma4-capable llama-cpp-python
An already-installed but too-old llama-cpp-python could not load the
gemma4 architecture ("Failed to load model from file"). The node now
requires llama-cpp-python >= 0.3.23 and upgrades an older install
automatically. Because a C-extension cannot be hot-reloaded, if an upgrade
was performed in a running session the node asks you to restart ComfyUI
once; it then works (and always falls back to the original prompt instead
of erroring).

May 18th, 2026  (v2.1.1)
1. Default model location moved into ComfyUI
The auto-downloaded default GGUF is now stored in and loaded from
ComfyUI/models/gguf/ (resolved via ComfyUI folder_paths) instead of the
global HuggingFace cache, so everything stays inside the ComfyUI directory.
An already-present file there is reused and never re-downloaded. Added a
.gitignore so models / *.gguf are never committed.

May 18th, 2026  (v2.1.0)
1. Split into two independent nodes
Description: The TIPO expansion is no longer embedded in the seasonal node.
Now there are two separate nodes (both category: prompt):
- "Seasonal Fashion Prompt Generator": the original CSV random combiner,
  reverted to its pure form with zero dependencies (the tipo_* inputs added
  in v2.0.0 were removed from this node).
- "Gemma TIPO Prompt -> Tags" (new): a standalone node that converts any
  Korean/English natural-language or tag text into a category-sorted
  Danbooru tag set. Inputs: prompt, tipo_gguf_path, tag_length, sort,
  temperature, ban_tags, seed.

2. Composable
Wire Node 1's output into Node 2's prompt input to expand a generated
seasonal prompt, or use Node 2 alone with your own text. Node 2 keeps the
first-use auto-install and optional HF auto-download; Node 1 stays
dependency-free.

May 17th, 2026  (v2.0.0)
1. TIPO Prompt Expansion (optional, opt-in via tipo_toggle)
Description: The node can now expand its generated prompt into a richer
Danbooru-style tag set using a local GGUF model run in-process by
llama-cpp-python, with prompt sorting done by kgen.formatter.

2. Bring-your-own / auto-download model
tipo_gguf_path: leave empty to auto-download the default model
(raspie/gemma4-tipo-ko-gguf) from HuggingFace on first use, or set a local
.gguf file/folder path to use your own.

3. First-use auto-install
On the first run with tipo_toggle on, missing dependencies
(llama-cpp-python via the prebuilt CPU wheel, tipo-kgen, huggingface_hub)
are installed automatically. With tipo_toggle off, nothing is installed and
the node behaves exactly as before (zero extra dependencies).

4. New optional inputs
tipo_toggle, tipo_gguf_path, tipo_tag_length (very_short..very_long),
tipo_sort (danbooru / quality_first / artist_first / general_only),
tipo_temperature, tipo_ban_tags.

5. Natural-language input
Korean (or English) natural-language descriptions of outfits or situations
are converted to English Danbooru tags; the raw description is not mixed
into the output. Any failure falls back to the un-expanded prompt.
