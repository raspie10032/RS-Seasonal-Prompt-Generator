May 18th, 2026  (v2.7.2)
1. Fix: vision mode returned empty ("no tags parsed")
Vision mode ran the mtmd CLI with --jinja, which loads the model's
embedded chat template. That template enables a hidden reasoning
("thought") channel, so gemma-4 spent the entire token budget thinking
and never emitted the final tag list -> the node parsed nothing and
returned empty. It now forces the built-in plain `gemma` chat template
(no thinking channel), so the model outputs the comma-separated Danbooru
tags directly. Verified end-to-end with the default Korean TIPO model.

May 18th, 2026  (v2.7.1)
1. Vision binary now auto-downloads on ALL platforms
The llama.cpp mtmd binary auto-download was Windows-only (other OSes
required setting LLAMA_MTMD_CLI by hand). It now picks and downloads the
correct prebuilt CPU build for the running OS/arch -- Windows / Linux /
macOS, x64 / arm64 -- with no build and no manual setup. The mmproj
already auto-downloads when mmproj_path is left empty. Vision mode is now
fully automatic everywhere.

May 18th, 2026  (v2.7.0)
1. Merged text + vision into ONE node
The "Gemma TIPO" text node and the "Gemma TIPO Vision" node are now a
single node: "Gemma TIPO (Prompt / Image -> Tags)". The image input is
optional -- connect a ComfyUI IMAGE to run vision mode (image -> tags),
leave it unconnected to run text mode (prompt -> tags). Both paths use
the same kgen post-processing. The separate vision node is removed.
2. New "simple" sort preset
Added a "simple" choice to the sort dropdown that outputs only
<|special|>, <|rating|>, <|general|> -- the leanest tag-only ordering.

May 18th, 2026  (v2.6.0)
1. New node: "Gemma TIPO Vision (Image -> Tags)"
Feed a ComfyUI IMAGE and it captions it into a rich, category-sorted
Danbooru tag set via Gemma-4 vision (llama.cpp mtmd) + the base
gemma-4-E2B mmproj. TIPO-style: capture + plausible expansion, not exact
labeling. Works with any gemma-4-E2B text/merged TIPO model from
ComfyUI/models/gguf (pairs with the auto-downloaded base mmproj).
On first use it auto-downloads a prebuilt llama.cpp mtmd binary and the
mmproj (no build); runs on CPU by default (gpu_layers=0) so it won't
fight other GPU work. Output goes through the same post-processing as
the text TIPO node (kgen sort / dedup / drop-redundant / count-conflict).
Any failure -> empty string (never hard-fails). Inputs: image, model,
tag_length, sort, temperature, ban_tags, seed, optional mmproj_path /
gpu_layers.

May 18th, 2026  (v2.5.0)
1. Resolve person-count conflicts
Each person-count group (girls / boys / others) is reduced to a single
tag: with "1girl" present, "4girls" / "multiple girls" etc. are dropped.
Groups are independent ("1girl" + "1boy" is kept). The kept tag is the
one in the user's input (first by input order), else the first in the
output. Tags like "cowgirl position" are not affected.

The seed widget had no min/max, so ComfyUI's randomize produced tiny

May 18th, 2026  (v2.4.0)
1. Drop redundant general tags
When a more specific tag with the same head noun is present, the general
one is removed to save tokens (e.g. with "white skirt" present, "skirt"
is dropped). Uses a safe suffix rule (the longer tag must end with
" " + the shorter), so distinct tags like "dress" vs "dress shirt" or
"skirt" vs "miniskirt" are NOT collapsed.

May 17th, 2026  (v2.0.0)
1. TIPO Prompt Expansion (optional, opt-in via tipo_toggle)
Description: The node can now expand its generated prompt into a richer
Danbooru-style tag set using a local GGUF model run in-process by
llama-cpp-python, with prompt sorting done by kgen.formatter.

2. Bring-your-own / auto-download model
tipo_gguf_path: leave empty to auto-download the default model
(raspie/gemma4-tipo-ko-gguf) from HuggingFace on first use, or set a local
.gguf file/folder path to use your own.

3. First-use auto-install
On the first run with tipo_toggle on, missing dependencies
(llama-cpp-python via the prebuilt CPU wheel, tipo-kgen, huggingface_hub)
are installed automatically. With tipo_toggle off, nothing is installed and
the node behaves exactly as before (zero extra dependencies).

4. New optional inputs
tipo_toggle, tipo_gguf_path, tipo_tag_length (very_short..very_long),
tipo_sort (danbooru / quality_first / artist_first / general_only),
tipo_temperature, tipo_ban_tags.

5. Natural-language input
Korean (or English) natural-language descriptions of outfits or situations
are converted to English Danbooru tags; the raw description is not mixed
into the output. Any failure falls back to the un-expanded prompt.
